# Orderak Glossary

> **Status:** Current terminology reference
>
> **Last verified:** 2026-07-19

Canonical definitions for all domain terms used across the codebase, API,
admin panel, and documentation. Arabic equivalents are provided in parentheses
where applicable.

## A

### ADMIN_API_KEY

Break-glass bootstrap key for creating the first admin owner via
`POST /api/admin/v1/auth/bootstrap`. Stored as a Cloudflare Worker secret.
Never entered in the browser panel; used only via `x-admin-key` header
for recovery operations.

### ADMIN_JWT_SECRET

Signing secret for admin session JWTs. Stored as a Cloudflare Worker secret.
Rotating it invalidates all existing admin sessions.

## C

### category_code

Immutable public identifier for a category, format `c-XXXXXX` (e.g. `c-A82KD9`).
Always resolves scoped to its owning store; cross-store access returns 404.
**Never changes** after creation. Stored in `categories.category_code`.

## D

### device secret

A per-device random credential generated on first launch. Sent as the
`x-orderak-secret` header on every authenticated request. Stored **hashed**
as `sha256$<hex>` in `sellers.secret` or `seller_devices.secret_hash` in D1 —
never in plaintext for newly stored credentials. Device secrets are random,
high-entropy tokens, so password-style key stretching is unnecessary. Legacy
PBKDF2 and plaintext values are accepted only for migration and are upgraded to
the SHA-256 format after successful authentication.

## E

### EMAIL_FROM

Optional environment variable / `.dev.vars` entry that overrides the default
transactional email sender (`Orderak <no-reply@orderak.app>`). Useful for
local development and testing.

## F

### FIREBASE_WEB_API_KEY

Web API key of the Firebase project. The Worker uses it to verify Firebase ID
tokens via Google Identity Toolkit on new-store registration and device restore.
Must be set in production as a Worker secret. If missing, registration fails
closed with `503 firebase_not_configured`.

### FORWARD_TO

Optional environment variable / `.dev.vars` entry. When set to a verified
Cloudflare Email Routing destination, each inbound email is also forwarded
there in addition to being stored in the admin Inbox.

## I

### idempotency key

A client-generated unique key sent via the `x-idempotency-key` header on
payment operations (`POST /api/v1/subscribe`). Allows safe retry without
double-charging. The backend records processed keys in the `webhook_events`
table and skips replays with `{ idempotent: true }`.

## M

### machine (translation status)

A product translation generated by the backend AI provider. Status `machine`
means the translation was produced automatically and has not been reviewed by
a human. See also: `reviewed`, `rejected`, `pending`.

## O

### order_no

A per-store, monotonically increasing integer assigned to each order.
Used as a sync cursor: the app passes `since=<last known order_no>` to
`GET /api/v1/orders` and receives only newer orders. Stored in `orders.order_no`.

## P

### PAYMENT_WEBHOOK_SECRET

HMAC shared secret for the current generic/mock payment-webhook contract.
Stored as a Cloudflare Worker secret. It is not a Stripe signing secret and the
backend does not currently implement Stripe's native webhook contract.

### pending (translation status)

A product translation that has been queued for AI generation but not yet
produced. The public storefront falls back to the seller-authored original text
until the status transitions to `machine`.

### piasters (قرش)

The base unit of currency throughout the entire codebase: Egyptian Pounds
(EGP) × 100, stored as an integer. Example: EGP 150.00 = 15000 piasters.
All API amounts use the `_piasters` suffix (e.g. `price_piasters`,
`total_piasters`). The Android UI explicitly divides by 100 for display.
**Never** use floating-point for money — it causes rounding errors.

### product_code

Immutable public identifier for a product, format `p-XXXXXX` (e.g. `p-H72LP9`).
Returned in sync and order responses so the Android app can match server data to
local Room records. **Never changes** after creation, even if the product is
deleted and re-created. Stored in `products.product_code`.

### public_identifier

The composite public URL identity for a store, constructed as
`{ISO2}-{slug}-{store_code}` (e.g. `EG-fresh-market-7KX9MP4R`).
Regenerated when the store name or slug changes, but the trailing `store_code`
**always stays the same** — so previously shared links keep working.
Stored in `sellers.public_identifier`.

## R

### rejected (translation status)

A machine translation that a human reviewer has explicitly marked as
unsatisfactory. The public storefront falls back to the seller-authored
original text. Rejected translations do not block new machine translations;
a subsequent source edit replaces the rejected status with a new `machine`
row.

### reviewed (translation status)

A translation that a human reviewer has approved. Includes a `reviewed_at`
timestamp. A source edit clears the review status and replaces it with a fresh
`machine` translation (because the old review is no longer valid for changed
content).

## S

### slug

A human-readable, editable segment of the public store URL. Normalized to
lowercase `a-z 0-9 -`, minimum 3 characters, non-Latin text transliterated
first. Example: `fresh-market`. Can be changed by the seller; when changed,
the `public_identifier` is regenerated but the `store_code` stays the same.
Reserved words (`api`, `admin`, `c`, `p`, `media`, `offers`, `branches`)
are blocked.

### source_locale

The detected locale of the seller-authored product content (name, description).
Stored in `product_translations.source_locale`. Used to determine which
direction to translate (e.g. Arabic source → English target).

### source_version

A SHA-256 hash of the seller-authored product name and description at the time
a translation was generated. Stored in `product_translations.source_version`.
When the current source hash differs from the cached version, the translation
is considered stale and regenerated.

### store_code

The **permanent, immutable** 8-character public identity for a store
(e.g. `7KX9MP4R`). Assigned once at registration and **never changes**.
This is the store's real identity — slugs and names can change, but the
`store_code` remains the stable anchor for links, redirects, and foreign
references. Stored in `sellers.store_code`.

### STRIPE_SECRET_KEY

Reserved future Stripe API key name. The current backend ignores this value and
always returns `MockGateway`; `BILLING_ENABLED=false` blocks paid acquisition in
the free-launch baseline. Do not configure or rely on this key until an approved
provider implementation, webhook contract, legal review, and tests exist.

## T

### translation_status

The lifecycle state of a cached product translation. One of:

- `pending` — queued, not yet generated
- `machine` — AI-generated, not yet reviewed
- `reviewed` — human-approved
- `rejected` — human-declined, fall back to original

Stored in `product_translations.translation_status`. See each status entry for
details.

## X

### x-idempotency-key

HTTP header carrying a unique client-generated key for idempotent payment
operations. See: **idempotency key**.

### x-orderak-phone

HTTP header carrying the seller's phone number in the format the app sends
(e.g. `01012345678`). Sent on every authenticated Android app request. Paired
with `x-orderak-secret`.

### x-orderak-secret

HTTP header carrying the seller's per-device random credential. Sent on every
authenticated Android app request. Paired with `x-orderak-phone`. The backend
compares it against the stored `sha256$` value in D1, with legacy PBKDF2 and
plaintext verification only for transparent migration. See: **device secret**.
